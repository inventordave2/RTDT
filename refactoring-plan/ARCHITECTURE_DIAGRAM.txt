KEY INSIGHT: UNIVERSAL FUNCTIONS
═════════════════════════════════════════════════════════════════════════════════

Functions used by BOTH browser and CLI (in raytracer-core.js):

    function renderSceneSync(world, camera, quality) {
        // Pure rendering logic
        // ✓ No DOM (no document.getElementById)
        // ✓ No fs (no require('fs'))
        // ✓ No Window APIs
        // ✓ No Process APIs
        // Just pure math and logic
        
        var pixels = [];
        for (var y = 0; y < HEIGHT; y++) {
            for (var x = 0; x < WIDTH; x++) {
                var ray = camera.ray_for_pixel(x, y);
                var color = color_at(world, ray, quality);
                pixels.push(color);
            }
        }
        return pixels;
    }

Browser calls it:
    renderImage() → renderSceneToPixels() → renderSceneSync()
                                            ▲
                                    Shared logic!
                                            
CLI calls it:
    main() → renderSceneSync()
             ▲
    Shared logic!

Browser renders the SAME pixels as CLI, just displays them differently:
  - Browser: Draws to <canvas> with ctx.fillStyle and ctx.fillRect
  - CLI: Writes to .ppm file with fs.writeFileSync

Same algorithm, different output 📊

   a) Add click handlers               a) Parse args
